# WebKVM — 使用手册

安装后如何使用 WebKVM。安装与技术文档请参阅
[INSTALLATION.md](INSTALLATION.md)。

[**English**](../USAGE.md) • [**Español**](../USAGE.es.md) • [**简体中文**](USAGE.md)

## 1. 首次登录

1. 打开安装器打印的 URL（默认 `https://IP:8080`，如果选择了纯 HTTP 则为
   `http://IP:8080`）。
2. 使用 `admin` 登录，密码保存在
   `/opt/webkvm/admin-password.initial`（安装结束时也会显示）。
3. 首次登录时系统会要求你**修改密码**。

使用自签名证书时，浏览器首次访问会警告。要消除警告，请从
`https://IP:PORT/api/system/cert` 下载证书并在操作系统中信任它。

## 2. 界面

界面是带侧边栏的单页应用：

| 标签页 | 功能 |
|-----|--------------|
| **虚拟机** | 虚拟机列表/网格、创建、电源操作、控制台。 |
| **存储** | 磁盘池、卷、ISO 库。 |
| **网络** | NAT/网桥网络、宿主机网桥、防火墙。 |
| **备份** | 目标、计划、作业、归档和恢复。 |
| **用户** | 账户、角色、组、API 令牌。 |
| **状态** | 后端、libvirt、宿主机状态和日志。 |
| **设置** | 服务器配置（端口、TLS、CORS 等）。 |

## 3. 虚拟机

### 创建虚拟机

1. 进入 **虚拟机 → 新建虚拟机**。
2. 选择操作系统（OS 预设会设置固件 UEFI/BIOS、TPM/安全启动、磁盘总线、内存/vCPU）。
3. 从**存储**库挂载 ISO（或上传一个）。
4. 选择网络（NAT 用于隔离的互联网访问，或网桥用于获得真实的局域网 IP）。
5. 高级选项：推荐的磁盘性能（`cache=none, io=native`）、空间回收
   discard/TRIM、带常用预设的 CPU 型号下拉框（或"自定义"手动指定型号），以及
   显式的 CPU 拓扑（插槽/核心/线程）而非扁平的 vCPU 数量。始终会附加 virtio 硬件
   RNG（无需开关）。
6. 创建它 —— 虚拟机会启动，之后即可打开其控制台。

### USB 设备直通（仅管理员）

在虚拟机的**接口**标签页中，管理员可以把宿主机的 USB 设备直接挂载到运行中或已停止的
虚拟机（也可以再次断开），并列出插在宿主机上的设备。

### PCI / GPU 直通（仅管理员）

在虚拟机的**硬件**标签页中，管理员可以把宿主机 PCI 设备（GPU、网卡、NVMe 控制器……）
绑定到已停止的虚拟机。WebKVM 会先执行**预检** —— 检查 IOMMU 已启用、设备的 IOMMU
分组已隔离、`vfio-pci` 可用 —— 如果该分组会连带无关设备，则拒绝挂载。

### 模板与 cloud-init

- **创建模板**：在虚拟机关机状态下，使用"制作模板"。之后可以基于它派生新虚拟机。
- **cloud-init（NoCloud）**：实例化模板时，可以自动配置用户、密码、SSH 密钥和主机名。
- **克隆**：一键复制现有虚拟机（包含磁盘）。

#### 与所有用户共享模板（仅管理员）

默认情况下，模板仅对其所有者以及普通 ACL、分组和标签规则已授予访问权限的对象可见。
模板详情页有一个**"与所有用户共享"**开关，只有管理员可以切换。

共享之后：

- **每个用户都可以列出并实例化它**，不受所有者、分组或标签访问权限限制。该开关
  *绕过*常规的作用域限制 —— 它不是额外的 ACL 条目，因此启用前请审阅模板内容。
- **每次实例化都会完整复制模板的磁盘。** 十位用户实例化一个 40 GiB 的模板会占用
  400 GiB。正因如此，界面会在开关旁显示此警告。
- **克隆共享模板不会继承该标志。** 克隆出来的模板会恢复为私有，必须由管理员再次
  有意共享。

再次关闭该开关会让模板对其他用户隐藏；但不会影响已由它创建的实例。

### 生命周期与快照

- 电源操作：启动、关机、重启、挂起、恢复、强制停止。
- **快照**：在虚拟机详情页创建（仅磁盘或包含内存），查看带历史的树状结构，回滚或删除。
  运行中虚拟机的仅磁盘快照在客户机代理可用（通过 cloud-init 预装的
  `qemu-guest-agent` 静默）时具有文件系统一致性，否则回退为崩溃一致性快照。
- **磁盘扩容**：在虚拟机关机时扩容磁盘（任意修改），或在运行中扩容（仅增大，仅
  qcow2 磁盘）—— 为运行中的虚拟机磁盘增加空间无需停机。
- **自动启动**：标记虚拟机在宿主机启动时自动开机。

### 控制台与图形

- **浏览器内 VNC 控制台**：在虚拟机详情页（内嵌 noVNC）。连接断开时会按退避策略
  自动重连；其侧边栏面板提供图像质量/压缩滑块、点状光标开关，以及无需离开控制台
  即可使用的电源操作（重启/关机/强制停止）。
- **串口控制台**：内嵌终端（80×24），可在客户机重启后继续工作。
- **SPICE/RDP**：下载 `.vv`（SPICE）或 `.rdp` 文件供外部客户端使用。其中写入的 IP
  来自 `PUBLIC_HOST` 或首个非回环地址。
- 所有内嵌控制台（串口、宿主机终端、VNC）都通过短期临时凭证认证 —— 长期会话凭据
  绝不会出现在 URL 中。VNC 临时凭证限定于该虚拟机和控制台相关操作，一小时后过期
  （在该时间窗内可复用，因为控制台可能重连且其电源按钮也需要它），而串口/宿主机
  终端使用的是一次性、30 秒的临时凭证。

## 3.1. 容器（LXC）

WebKVM **原生管理 LXC 容器**（由独立安装器默认安装；参见
[INSTALLATION.md](INSTALLATION.md) → "容器（LXC）"）。容器与虚拟机共享同一界面：

- **统一列表**：容器与虚拟机一起显示，每张卡片带有 `KVM`/`Incus` 徽标和配置状态
  标签；`全部 · 虚拟机 · 容器` 筛选可缩小列表。
- **创建**：使用相同的"创建"表单，将实例类型选择为 **容器（Incus / LXC）** ——
  从镜像下拉框选择发行版（或"自定义 / 其他…"）、选择网络（与虚拟机相同的网桥），
  并设置 **Incus / LXC 凭据**（用户名可选；留空 = 密码应用于 `root`）。无需 ISO，
  无需手写 YAML。
- **存储池**：向导第 3 步（"资源"）提供**存储池**选择器，仅列出用途为 `container`
  的存储池（默认为 `webkvm-incus`）。虚拟机磁盘、ISO、备份和模板存储池绝不会出现
  在那里 —— 创建 KVM 虚拟机时容器存储池也绝不会出现，因为 libvirt 与 Incus
  管理的是两个独立的世界。
- **详情**：容器支持根磁盘**扩容**、**添加/移除/更改**网络接口、串口控制台和实时
  CPU/内存**指标**。仅 KVM 可用的控件（芯片组/UEFI/TPM、VNC、CD-ROM、客户机代理
  密码重置、克隆）会隐藏。

#### 将容器迁移到另一个存储池

使用容器详情页侧边栏中的**"移动存储"**。它会通过 Incus 的原生迁移把根文件系统 ——
包括快照 —— 迁移到另一个 `container` 存储池，并报告字节级进度。

- 容器**必须处于停止状态**；运行中的实例会被拒绝。
- 目标必须是*不同的* `container` 存储池。
- **跨虚拟机监控程序**的移动（KVM 存储池 ⇄ Incus 存储池）按设计会被拒绝。请改用
  导出和重新导入。

> 存储页面的 **LXC** 标签页有意不提供移动按钮。容器根文件系统是由其实例拥有的
> `container` 类型卷，而不是可分离的 `custom` 卷，因此要从实例页面移动 —— 而不是
> 从卷列表移动，它在卷列表中不会出现。

## 4. 存储

- **存储池**：后端在 `/opt/webkvm/pools` 下管理自己的存储池：
  - `webkvm-disks` —— 虚拟机磁盘。
  - `webkvm-isos` —— ISO 镜像。
  - `webkvm-incus` —— 容器根文件系统（容器模块开启时）。
- 可以创建额外的 `dir`（本地）或 `netfs`（NFS/SMB/CIFS）类型存储池；用途为 `iso`
  的存储池对卷操作只读。
- **用途**：每个存储池声明它可以存放什么 —— `disk`（libvirt qcow2/raw）、
  `container`（Incus 根文件系统）、`iso`、`backup` 或 `template`。一个存储池可以
  组合多种用途。用途是界面中每个存储池选择器的筛选依据，因此容器永远不会落到
  虚拟机磁盘池，qcow2 也永远不会落到 ISO 库。
- **迁移存储**：虚拟机磁盘从**存储 → 磁盘 → 移动**；容器根文件系统从其
  **实例详情页**移动（见上文"容器（LXC）"）。跨虚拟机监控程序移动是不可能的。
- **卷**：在存储池中创建、扩容和删除磁盘，或**上传现有磁盘镜像**
  （`.qcow2`、`.img`、`.raw`、`.qed`）直接到存储池 —— 文件会直接流式写入磁盘，
  libvirt 在刷新时自动检测其格式，无需转换。
- **ISO 库**：从网页上传、下载（带进度）和删除 ISO。

### 需要认证的 CIFS（SMB）网络存储池

要使用凭据挂载 SMB3 共享（例如用于备份）：

1. **存储 → 新建存储池**，类型 `netfs`，格式 `cifs`，填写 `source_host`、
   `source_dir`、`source_username` 和 `source_password`。
2. 密码以 **libvirt secret** 形式存储（API 永不返回；磁盘上仅保留其 UUID）。
3. 通过更新存储池来轮换凭据（存储池必须处于停止状态）。
4. 如果重装了 libvirtd，通过发送 `cifs-needs-reauth: true` 加当前凭据来恢复存储池。

## 5. 网络与防火墙

### 宿主机网桥

WebKVM 使用**操作系统层面真正的 Linux 网桥**（Proxmox 风格）；libvirt 虚拟网络
（`default`、`virbr0`、……）已不复存在。

- **共享 L2 `vmbr0`/`br0`**（默认，推荐）：虚拟机和容器接入真实局域网，并从路由器
  获取 IP（DHCP 或静态）。
- **隔离 NAT `vmbr1`**（需显式启用）：基于内核 `dummy` 接口的 Linux 网桥，地址
  `100.0.0.1/24`，带 `dnsmasq` DHCP 和 `MASQUERADE`。
- 可在**网络**页面创建带可选 IP + 自定义 DHCP 范围（起始/结束、网关、DNS）的额外
  **宿主机网桥**，并为每个网桥切换自动启动。

### 每虚拟机防火墙

在虚拟机详情页：

- **入站规则**（nftables）用于暴露特定端口。
- **端口转发**从宿主机到虚拟机。

规则以原子化方式应用，并带有防止把自己锁在 SSH 之外的保护措施。

## 6. 备份

1. 创建备份**目标**（本地文件夹或 NFS/SMB/SFTP 挂载）。
2. 创建**计划**（cron 表达式）或手动运行一次。
3. 运行器为每台虚拟机生成一个归档（`vm-<name>.tar.zst`）以及一个配置归档
   （`config.tar.zst`），可选 SHA-256 校验和自动保留策略（保留最近 N 份 / 保留 N 天）。
4. **恢复**：完整恢复（带大小限制和受保护路径检查）或"恢复为虚拟机"（把备份重新
   导入为新虚拟机）。
5. 密钥（webhook、SMTP、SFTP、CIFS）绝不会包含在配置备份中。

进度会实时显示在通知中心和**备份 → 作业**下。

## 7. 告警与通知

为以下事件配置 **webhook（HTTPS）** 或**邮件（SMTP）**通知：

- 虚拟机意外宕机。
- 磁盘空间不足。
- 备份成功/失败。

## 8. 配额与调度

- **每用户配额**：虚拟机数量、vCPU、内存和磁盘的限制 —— 在创建、克隆、导入、恢复
  和扩容时强制执行。管理员不受限制。
- **虚拟机调度**：基于 cron 的自动开机/关机（例如夜间关闭测试虚拟机）。

## 9. 用户、角色与 API

### 角色（RBAC）

| 角色 | 能力 |
|------|--------------|
| **admin** | 一切：用户、设置、节点、备份、破坏性操作。 |
| **operator** | 创建/编辑/删除虚拟机、电源操作、磁盘、网络、存储池、备份。 |
| **viewer** | 只读。 |

- 在**用户**标签页创建用户并分配角色/组。
- 用户从**账户**修改自己的密码。
- 首次登录时必须修改初始密码。

### API 令牌

在**账户 → API 令牌**中创建长期令牌（`wvmb_…`）用于脚本。使用请求头
`Authorization: Bearer <token>`。仅存储 SHA-256 哈希。令牌会过期（默认 30 天）
且可吊销。

### 审计日志

每个敏感操作都会记录在 `/opt/webkvm/audit.log`（JSONL）中，包含用户、角色、操作、
资源和来源 IP。

## 10. 社区应用

**社区应用**对话框可从官方云镜像（Ubuntu、Debian、Rocky、CentOS Stream、Fedora、
Arch、Alpine、openSUSE）部署开箱即用的虚拟机，另有一键式应用（Home Assistant OS、
OpenWrt、OPNsense）以及基于 Ubuntu 24.04、在首次启动时安装的一键应用（WordPress、
Nextcloud、Odoo、Moodle）。

选择用户名/密码（cloud-init 镜像必填）、目标网络和虚拟机名称；部署作为后台任务
运行，并显示实时进度。

## 11. 日志与故障排查

```bash
systemctl status webkvm           # 服务状态
journalctl -u webkvm -f           # 实时日志
cat /opt/webkvm/logs/backend.log  # 启用 WEBKVM_LOG_FILE 时
```

| 现象 | 修复 |
|---------|-----|
| 服务无法启动 | `systemctl status webkvm` + `journalctl -u webkvm -n 100` |
| 缺少 `/dev/kvm` | 在 BIOS 中启用虚拟化或嵌套虚拟化 |
| 浏览器证书警告 | 从 `/api/system/cert` 下载证书并信任它 |
| 无法连接 libvirt | 检查 `systemctl status libvirtd`；后端以 root 运行 |
| 无法从 ISO 创建虚拟机 | 先在**存储**中上传 ISO，再挂载它 |
| 串口控制台提示虚拟机已关闭 | 启动虚拟机；控制台会在下次尝试时自动重连 |
